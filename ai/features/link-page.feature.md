# 🤖 AI Feature Spec — Link Page

---

## Feature Identity

- **Feature Name:** Link Page
- **Related Area:** Public-Facing Page / Professional Links
- **R1 Reference:** Section "Feature - Link page"
- **Spec File:** `./ai/features/link-page.feature.md`

---

## Feature Goal

Build the public links page at `/#/links`. The page displays at least 3 professional links as structured cards — each with an image, title, short description, and a clickable URL that opens in a new tab. At least one image on the page must be AI-generated.

---

## Feature Scope

### In Scope (Included)

- `src/pages/Links.jsx` — replaces the current stub with full content
- `src/pages/Links.css` — page-specific styles
- At least 3 link cards, each with: image, title, description (1–3 sentences), external URL (new tab)
- At least 1 AI-generated image on the page (card thumbnail or decorative element)
- LOGIC BRIEFING and SECTION comments on `Links.jsx`

### Out of Scope (Excluded)

- Contact form — belongs to `contact-page` feature
- Authentication — belongs to `login-page` feature
- Dynamic data from Supabase — all content is static

---

## Sub-Requirements (Feature Breakdown)

- **SR-1 — AI Feature Specification** — This file. Created before implementation begins.
- **SR-2 — Link cards** — At least 3 cards rendered, each containing: image thumbnail, title, 1–3 sentence description, and a clickable URL that opens in a new tab (`target="_blank"` + `rel="noopener noreferrer"`).
- **SR-3 — AI-generated image** — At least 1 image on the page generated by an AI tool. AI tool documented in Tech Constraints below.
- **SR-4 — Responsive** — Cards stack vertically on mobile (≤768px). Images scale within cards. No horizontal overflow.

---

## Interfaces (Pages, Endpoints, Screens)

### Frontend

- `src/pages/Links.jsx` — full page replacing the stub
- `src/pages/Links.css` — page-specific card layout and styles
- `src/assets/` — image assets for link card thumbnails

### Backend / API

- N/A — no Supabase calls on the Links page

---

## Data Used or Modified

- No application data is created or stored.
- All link content is static — titles, descriptions, URLs, and images are hardcoded in the component.

---

## Tech Constraints (Feature-Level)

- **External links:** All card URLs must use `target="_blank"` and `rel="noopener noreferrer"` for security.
- **Images:** At least 1 card image must be AI-generated. Images saved in `src/assets/` and imported in `Links.jsx`. Document the AI tool used here: `[AI tool: GitHub Copilot — 3 branded SVG thumbnails: LinkedIn, Resume, GitHub]`.
- **Colors:** All color values from `src/constants/brandColors.js`. No hardcoded hex values.
- **LOGIC BRIEFING:** Required on `Links.jsx`.
- **Responsive:** Card grid collapses to 1 column at ≤768px.

---

## Runtime User Flow

1. Visitor clicks "Links" in the navigation.
2. The Links page renders inside the Layout (Header + Footer visible).
3. The visitor sees a grid of at least 3 cards.
4. Each card shows an image, a title, a short description, and a clearly clickable link.
5. Clicking a card link opens the external URL in a new browser tab.
6. On mobile, cards collapse to a single column with no overflow.
