# 🤖 AI Feature Spec — Portfolio Page

---

## Feature Identity

- **Feature Name:** Portfolio Page
- **Related Area:** Public-Facing Page / Resume & Work History
- **R1 Reference:** Section "Feature - Portfolio page"
- **Spec File:** `./ai/features/portfolio-page.feature.md`

---

## Feature Goal

Build the public portfolio page at `/#/portfolio`. The page presents Damien McCullor's education history, professional work experience, and project showcase — organized into at least 3 visually distinct sections — along with a downloadable PDF resume and at least two AI-generated images.

---

## Feature Scope

### In Scope (Included)

- `src/pages/Portfolio.jsx` — replaces the current stub with full content
- `src/pages/Portfolio.css` — page-specific styles
- Education section: at least 1 entry with institution name, degree/program, and dates (reverse chronological)
- Work experience section: at least 1 entry with title/role, organization, dates, and description of responsibilities/achievements (reverse chronological)
- Project/portfolio section: at least 1 project with name, tech stack, description, and image
- Downloadable PDF resume link (file at `public/resume.pdf`)
- At least 2 AI-generated images with `alt` text
- LOGIC BRIEFING and SECTION comments on `Portfolio.jsx`

### Out of Scope (Excluded)

- Contact form — belongs to `contact-page` feature
- Authentication or admin features
- Dynamic data from Supabase — all content is static

---

## Sub-Requirements (Feature Breakdown)

- **SR-1 — AI Feature Specification** — This file. Created before implementation begins.
- **SR-2 — Education section** — At least 1 entry listing institution name, degree/program, and dates. Entries in reverse chronological order.
- **SR-3 — Work experience section** — At least 1 entry listing title/role, organization, dates, and description of responsibilities or achievements. Entries in reverse chronological order.
- **SR-4 — Project/portfolio section** — At least 1 project entry with: project name, tech stack, description of purpose, and an associated image.
- **SR-5 — Downloadable PDF resume** — A link/button that triggers download of `public/resume.pdf`. File must be placed in `public/` so Vite serves it at the root.
- **SR-6 — Layout** — At least 3 distinct sections (Education + Work + Projects). Sections visually separated by spacing, background colors, or dividers.
- **SR-7 — AI-generated images** — At least 2 images generated by an AI tool placed in `src/assets/` and rendered in `Portfolio.jsx` with non-empty `alt` attributes. AI tool documented in Tech Constraints below.
- **SR-8 — Responsive** — All sections stack vertically on mobile (≤768px). Images scale within their containers. No horizontal overflow.

### Backend / API

---

## Data Used or Modified

- No application data is created or stored.
- All content is static — education, work, and project entries are hardcoded in the component.
- `public/resume.pdf` is a static file served directly by Vite/GitHub Pages.

---

## Tech Constraints (Feature-Level)

- **PDF download:** Link must use `href="/resume.pdf"` with `download` attribute. File must be in `public/` — NOT in `src/assets/` (which gets hashed by Vite).
- **Images:** AI-generated images saved in `src/assets/`. Minimum 2 images. Document the AI tool used here: `[AI tool: GitHub Copilot — 4 SVG project thumbnails generated as branded diagrams]`.
- **Colors:** All color values from `src/constants/brandColors.js`. No hardcoded hex values in `Portfolio.jsx` or `Portfolio.css`.
- **LOGIC BRIEFING:** Required on `Portfolio.jsx`.
- **Responsive:** Section containers must stack at ≤768px. Images must respect `max-width: 100%`.

## Runtime User Flow

1. Visitor clicks "Portfolio" in the navigation.
2. The Portfolio page renders inside the Layout (Header + Footer visible).
3. The visitor sees the education section with at least one institution entry.
4. Scrolling down, the visitor sees the work experience section with role, org, dates, and description.
5. Continuing to scroll, the visitor sees the projects section with at least one project card showing name, tech, description, and image.
6. A "Download Resume" button/link is visible; clicking it downloads `resume.pdf`.
7. AI-generated images are visible inline within the relevant sections with descriptive alt text.
8. On mobile, all sections collapse to a single column and images scale to fit the viewport.
